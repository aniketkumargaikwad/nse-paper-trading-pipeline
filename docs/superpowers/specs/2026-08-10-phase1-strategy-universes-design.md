# Phase 1 — Strategy Format v2 and Symbol Universes

**Status:** Approved · **Date:** 2026-08-10

The second of six phases. Phase 0 built a precise candle store; this phase
makes strategies something you can **author, paste, and point at a universe**
instead of a hand-typed list of five symbols.

---

## 1. Why this phase exists

Three concrete problems block everything downstream.

**Strategies name symbols one at a time.** `instruments:` is a literal list.
Phase 2's batch backtest engine is supposed to answer "does this edge hold
across Nifty 100", and there is currently no way to even express that question.
The `symbol_groups` tables were created in Phase 0 and left deliberately empty,
waiting for this phase.

**v1's sizing model cannot express a viable strategy.** Measured during Phase 0:
a ~₹30 round-trip cost against a 1.5% target at `quantity: 1` loses money on
most large caps regardless of whether the signal is any good. Worse for a
universe, the distortion is *uneven* — at a fixed share count, cost drag is 15%
of the move on a ₹200 stock and 0.75% on a ₹4,000 one. Ranking 100 symbols that
way substantially ranks them by share price. This is a **measurement** defect,
not a money one, which is why it belongs in the format rather than in a
position-sizing feature later.

**There is no single place a strategy lives.** `strategies.yaml` is declared the
source of truth, and `db.sync_strategies()` mirrors it into Supabase while
disabling anything absent from the file. That arrangement cannot accommodate
either authoring route the platform needs: pasting a strategy generated by an
external AI tool (the TradingView/Pine-Script workflow), or building one by
selecting parameters in the UI.

### Non-goals for this phase

- AI-assisted authoring *inside* our system — deliberately deferred. The
  external workflow (generate in ChatGPT, paste here) is supported instead, and
  `docs/STRATEGY_FORMAT.md` is what makes it work.
- The batch backtest engine and metric suite — *Phase 2*
- Strategies grid, detail page, results popup — *Phase 3*
- Paper-trading deployment and performance page — *Phase 4*
- Live broker execution — *Phase 5*
- Shared-capital portfolio simulation. Position sizing here is per-symbol and
  independent; capital allocation is not modelled. This is a testing and
  paper-trading platform, so what matters is whether an edge exists, not what a
  particular account balance would have done.

## 2. Decisions and the reasoning behind them

### 2.1 The database owns a strategy; `strategies.yaml` is demoted to a seed

Both authoring routes — paste and form-builder — are the application writing a
strategy. A file-owned model makes both impossible, because a file-owned
strategy can only be changed by editing a file and committing it.

So Supabase `strategies` becomes authoritative. `strategies.yaml` ships as a
starter example and first-run bootstrap, nothing more.

**Consequence that must be handled:** `db.sync_strategies()` disables every
strategy not present in the YAML. Under the new ownership that silently
disables everything you author in the app. It is **removed** in this phase, not
adapted. `seed_strategies_if_empty()` remains and is now the only file→DB path.

**Cost accepted:** strategies stop being git-versioned. Reproducibility is
addressed at the point it actually matters — §2.3 records the exact strategy
document and resolved symbol list with each backtest run.

### 2.2 Invalid strategies are saved as drafts, not rejected

A strategy arriving from ChatGPT is *expected* to be wrong on first attempt —
an invented indicator, a misspelled key, a timeframe we do not serve. Rejecting
the paste outright means retyping or re-prompting from scratch.

Drafts are stored with their original text and their error list, are editable in
the form builder, and **cannot be run**. Enforcement is a single filter in
`list_strategies()` (`status='valid' AND enabled`), so there is exactly one
place where "can this execute" is decided.

Auto-correction was rejected: a silently repaired strategy backtests as
something other than what was pasted, without saying so.

### 2.3 `universe:` is a live reference, and each run records what it resolved to

Index membership changes, and stocks are *added* to an index after they have
already risen. Backtesting today's NIFTY100 over past years therefore tests a
list partly selected for having gone up — survivorship bias that is invisible
unless the design exposes it.

Three options were considered:

| | Behaviour | Trade-off |
|---|---|---|
| Reference only | Members resolve fresh each run | Always current; two runs a month apart silently test different sets |
| Snapshot at save | Resolved once, frozen | Reproducible; drifts stale, missing rebalances |
| **Reference + per-run snapshot** ✅ | Resolves fresh, records what it used | Current *and* reproducible after the fact; one extra column in Phase 2 |

**Chosen: reference + per-run snapshot.** The strategy stores `universe:
NIFTY100`; each backtest run records the resolved symbol list and the
constituent-list date.

**Documented limitation:** this is *today's* membership applied to past data,
not point-in-time membership. Free historical constituent data does not
meaningfully exist. The chosen option does not remove the bias — it makes it
visible and states it on the result, which is the only honest option available.

### 2.4 Constituents: fetch from NSE, with a committed snapshot fallback

NSE publishes index constituent CSVs (`Company Name, Industry, Symbol, Series,
ISIN Code`). Dhan's security master carries segment and series but **no index
membership**, so it cannot be a source here.

NSE's endpoints are unofficial and bot-hostile. Live-only fetching therefore
means universes stop resolving whenever NSE changes or blocks — and an
unresolvable universe produces a zero-trade backtest that reads exactly like
"no signals found." So every list is also committed as a dated snapshot, and
resolution falls back to it with a loud, dated warning.

### 2.5 Trade size in rupees, not shares

`notional_per_trade` replaces `quantity` as the recommended sizing mode.
Quantity is derived per symbol as `floor(notional / entry fill price)`, making
cost drag identical across the universe so what survives comparison is the edge.

`fixed_quantity` is **retained as a legacy sizing type**, documented as
discouraged. Removing it would invalidate every v1 strategy already written and
force each to be re-sized by hand, and migration cannot infer a sensible
notional from a share count without inventing a price.

### 2.6 Storage cost of large universes is stated up front

At the 5-minute base, per §2.2 of the Phase 0 design:

| Universe | Symbols | ~Rows (2 yr) | ~Size |
|---|---|---|---|
| NIFTY50 | 50 | 1.9 M | ~230 MB |
| NIFTY100 | 100 | 3.8 M | ~450 MB |
| NIFTY500 | 500 | 18.8 M | ~2.2 GB |

Supabase free tier is 500 MB; Pro is 8 GB at $25/mo. NIFTY500 is therefore a
decision with a bill and a long Dhan backfill attached. The universe resolution
path reports the projected row count and storage before a large backfill starts,
rather than letting it be discovered midway.

## 3. Architecture

```
   strategies.yaml ──(seed, first run only)──┐
                                             ▼
   paste box ────► text ─┐          ┌──────────────────┐
                         ├─► parse ─┤  strategies      │
   form builder ─► dict ─┘   (pure) │  (Supabase)      │
                                    │  valid | draft   │
                                    └────────┬─────────┘
                                             │ status='valid'
                                             ▼
                              backtest engine · paper engine
                                             │
                                             │ universe: NIFTY100
                                             ▼
                                     ┌───────────────┐
   NSE index CSVs ──► universes.py ─►│ symbol_groups │
   committed snapshots ──────────────└───────────────┘
```

Two properties carry the design:

1. **Both authoring doors converge on one parser.** The form builder cannot
   produce anything the paste box could not, so they can never disagree.
2. **Parsing is pure — no network, no database.** Validating a pasted strategy
   works offline and is fully unit-testable.

### 3.1 Modules

| Module | Responsibility | Depends on |
|---|---|---|
| `strategy/vocabulary.py` | What is legal: indicators, operators, sizing types, stop types, timeframes. Pure data | — |
| `strategy/parse.py` | dict → validated `Strategy`; owns every error message | `vocabulary`, `config` |
| `strategy/migrate.py` | v1 document → v2 document, one-way and explicit | `vocabulary` |
| `strategy/__init__.py` | Re-exports `Strategy`, `parse_strategy_dict`, `StrategyConfigError` | the above |
| `universes.py` | NSE fetch, snapshot load, name → symbols, resolution reporting | `instruments`, Supabase |
| `strategy_schema.py` | Thin re-export shim; keeps existing imports and the CLI working | `strategy/` |

`strategy_schema.py` is 22 KB today; v2 would push a single file past ~1,200
lines covering vocabulary, parsing, migration and universes at once. Splitting
keeps the error-message path — the thing that matters most now that malformed
input is the common case — in one focused module.

Dependencies run one way: `vocabulary` ← `parse` ← `migrate`. `universes.py`
does not import from `strategy/` at all; a strategy holds a universe *name* as
a string and resolution happens in the caller at run time.

**Rejected: rewriting validation on pydantic.** The existing module rejects it
for producing cryptic errors, and that reasoning is stronger now — with
ChatGPT-generated input, error quality *is* the feature.

## 4. Format v2

```yaml
version: 2

strategies:
  - name: TF-EMA-RSI-15m-v2
    enabled: true
    position_type: long          # long | short
    timeframe: 15m               # 5m | 15m | 25m | 30m | 60m | day

    universe: NIFTY100           # exactly one of universe / instruments
    # instruments: [NSE:TCS, NSE:INFY]

    entry:                       # unchanged from v1
      all:
        - indicator: ema
          params: { period: 9 }
          operator: crosses_above
          compare_to: { indicator: ema, params: { period: 21 } }

    exit:
      any:
        - indicator: rsi
          params: { period: 14 }
          operator: "<"
          value: 40

    sizing:
      type: notional             # notional | fixed_quantity (legacy)
      notional_per_trade: 100000

    risk:
      stop_loss:     { type: percent, value: 0.7 }
      target:        { type: percent, value: 1.5 }
      trailing_stop: { type: percent, value: 0.5 }   # optional
      # atr form:    { type: atr, period: 14, multiplier: 1.5 }

    session:                     # every key optional
      no_entry_before: "09:30"
      no_entry_after:  "14:30"
      square_off:      "15:15"

    max_cycles_per_day: 2
```

`entry` and `exit` are **unchanged from v1** — same operands, operators, and
`all`/`any` nesting. Everything new is in `sizing`, `risk`, `session`, and the
`universe` alternative to `instruments`.

### 4.1 Semantics

These are the points where an imprecise spec becomes a wrong backtest. All times
are IST; all evaluation is on **closed candles only**, per v1.

**Quantity.** `floor(notional_per_trade / entry fill price)`. If that is 0 — the
share costs more than the notional — the trade is **skipped and recorded as
skipped**, naming the symbol and price. A quantity-0 trade is never produced.

`notional_per_trade` is **required** with no default. A default would be a
silent opinion about how much cost drag is acceptable, and the whole point of
§2.5 is to stop that decision being made implicitly.

**`max_cycles_per_day` is per symbol, per day** — not per strategy. A strategy
over a 100-symbol universe with `max_cycles_per_day: 2` may take up to 2
round-trips in *each* symbol. This matches v1's existing behaviour, where each
symbol is simulated independently, and follows from the per-symbol position
model (§1, non-goals).

**ATR stops.** ATR is computed on the strategy's own timeframe and read from the
last closed candle before the fill. It is fixed for the life of the trade unless
`trailing_stop` is set. Insufficient history is a hard error (§6), not a silent
zero-trade result.

**Trailing stop.** Updates at candle *close*, using that candle's high (long) or
low (short), and applies from the **next** candle onward. Updating and
triggering inside the same candle would be look-ahead. The effective stop is
always the tighter of the fixed and trailing levels, so a trailing stop can only
ever move in the position's favour.

**Entry window.** `no_entry_before` / `no_entry_after` apply to the **fill**
candle's time, not the signal candle — the fill is when the position actually
opens.

**Square-off.** Closes at the open of the first candle starting at or after the
configured time, and blocks entry fills at or after it. A strategy with
`square_off` set never holds a position overnight.

**Exit precedence within one candle** extends the engine's existing worst-case
convention, in order: signal exit → stop loss (incl. trailing) → target →
square-off. A gap through a level fills at the candle open, not at the level.

**Universe vs instruments.** Exactly one is required. `universe` names a row in
`symbol_groups`; `instruments` is the v1 literal list, still fully supported.

### 4.2 v1 → v2 migration

Mechanical and lossless:

| v1 | v2 |
|---|---|
| `risk.stop_loss_pct: 0.7` | `risk.stop_loss: {type: percent, value: 0.7}` |
| `risk.target_pct: 1.5` | `risk.target: {type: percent, value: 1.5}` |
| `sizing: {type: fixed_quantity, quantity: N}` | carried over unchanged (legacy type) |
| `instruments: [...]` | unchanged |
| absent | `session:` omitted — no square-off, matching v1 behaviour exactly |

A migrated v1 strategy must backtest **identically** to before, which is
asserted by test rather than assumed. `version: 1` documents are migrated on
read and the migration is reported, never applied silently in place.

## 5. Data model

Additive changes only. No existing row is rewritten.

```sql
-- Drafts may contain anything, including an invalid timeframe or no
-- position_type at all. The typed columns therefore become nullable and are
-- populated only for valid rows; validity is decided by the validator, not by
-- scattered CHECK constraints that would disagree with it.
alter table strategies
    add column if not exists raw_source        text,      -- exactly what was pasted
    add column if not exists format_version    integer,
    add column if not exists status            text not null default 'valid'
        check (status in ('valid', 'draft')),
    add column if not exists validation_errors jsonb;

alter table strategies alter column enabled       drop not null,
                       alter column position_type drop not null,
                       alter column timeframe     drop not null,
                       alter column definition    drop not null;

-- Phase 0 added 5m and 25m; the original CHECK predates them.
alter table strategies drop constraint if exists strategies_timeframe_check;
alter table strategies add  constraint strategies_timeframe_check
    check (timeframe is null or timeframe in ('5m','15m','25m','30m','60m','day'));

-- Universes state their provenance and age.
alter table symbol_groups
    add column if not exists source             text not null default 'custom'
        check (source in ('nse', 'custom')),
    add column if not exists constituents_as_of date;
```

`symbol_groups` and `symbol_group_members` themselves are unchanged — they were
defined in Phase 0 and are populated for the first time here.

**RLS:** unchanged. `symbol_groups` and `symbol_group_members` already carry
anon read policies from Phase 0. The new `strategies` columns inherit that
table's existing policy; `raw_source` and `validation_errors` contain strategy
text only, never credentials.

## 6. Error handling

| Failure | Behaviour |
|---|---|
| Pasted text is not valid YAML | Saved as draft; error names the line and column from the YAML parser |
| Unknown indicator, key typo, bad operator | Draft; error names the exact path (`strategies[0].entry.all[1].operator`) and lists what is allowed — v1 behaviour, preserved |
| Both `universe` and `instruments`, or neither | Draft; error states that exactly one is required |
| Universe name does not exist | Draft. Checked at **save**, not parse, because parse is pure and offline: save runs `parse` then a universe-existence lookup |
| NSE fetch fails during refresh | Fall back to the newest committed snapshot and warn loudly, naming its date. Never an empty universe |
| Universe resolves partially | Missing symbols are named; the run reports 97/100 and never implies 100 |
| `notional_per_trade` below the share price | Trade skipped and recorded as skipped, with symbol and price |
| ATR period exceeds available history | Hard error naming the symbol, candles needed, and candles found |
| `version: 1` document | Migrated on read; the migration is reported |
| Supabase unreachable | Fail loudly; no degradation to a partial or cached strategy list |

The through-line, inherited from Phase 0: every "nothing happened" outcome must
be distinguishable from "something broke."

## 7. The ChatGPT handoff

`docs/STRATEGY_FORMAT.md` is a single self-contained page — vocabulary,
semantics, and a worked example — written to be pasted into an external AI tool
as context before asking it for a strategy.

Its indicator, operator, and sizing lists are **generated from
`strategy/vocabulary.py`**, and a test asserts the document matches the
validator. A format reference that drifts from what the parser accepts would
send you in circles debugging strategies that were never going to validate.

## 8. Testing

**Offline (no network, no credentials) — the bulk of the suite**

- Every v2 field, valid and invalid, asserting on **message content** rather
  than merely that an error was raised. These messages are now the primary
  interface for correcting AI-generated strategies.
- v1 → v2 migration, including that a migrated v1 strategy backtests
  identically to before.
- Sizing: quantity arithmetic and the 0-quantity skip.
- Trailing stop: the update-at-close / apply-next-candle ordering, tested
  explicitly for the look-ahead case.
- Square-off boundary candle; entry-window boundaries; stop-and-target-in-one-
  candle precedence.
- Universes: snapshot parsing, fetch-failure fallback, partial-resolution
  reporting.
- Storage: draft round-trip; `list_strategies()` excludes drafts;
  `seed_strategies_if_empty()` does not clobber existing rows.
- `docs/STRATEGY_FORMAT.md` generation matches `vocabulary.py`.

**Live (opt-in, one command)**

- One NSE constituent fetch, asserting shape and a plausible member count.

**Migration safety**

- Additive columns; existing rows default to `status='valid'`; no data rewrite.
- The full existing suite must stay green — `strategy_schema.py` remains a
  working import path and CLI throughout.

## 9. Risks

| Risk | Mitigation |
|---|---|
| NSE changes or blocks its constituent endpoints | Committed dated snapshots; resolution falls back and says so |
| Survivorship bias from current-membership universes | Cannot be removed without point-in-time data; each run records its resolved list and list date, and results state the caveat |
| Removing `sync_strategies` breaks an existing workflow | It is the only thing that could silently disable app-authored strategies; `seed_strategies_if_empty` covers the legitimate bootstrap case |
| NIFTY500 backfill exceeds the free tier mid-run | Projected row count and storage reported before a large backfill starts |
| Split into `strategy/` breaks existing imports | `strategy_schema.py` retained as a re-export shim; full suite green is the gate |
| Draft rows reaching an engine | Single `status='valid'` filter in `list_strategies()`, directly tested |

## 10. Definition of done

- [ ] A strategy pasted as text is validated and saved; a malformed one is saved
      as a draft with actionable errors and cannot be run
- [ ] The form builder and the paste box produce identical documents for the
      same strategy
- [ ] `universe: NIFTY100` resolves to instruments, reporting any unresolved
      names rather than dropping them
- [ ] NIFTY50/100/500 populated in `symbol_groups` from NSE, with snapshots
      committed and `constituents_as_of` set
- [ ] A universe still resolves with NSE unreachable, warning with the snapshot
      date
- [ ] Every v1 strategy migrates to v2 and backtests identically
- [ ] Notional sizing derives quantity per symbol; a too-small notional is a
      recorded skip, not a zero-quantity trade
- [ ] Trailing stop, ATR stop, entry window and square-off each behave per §4.1,
      with the look-ahead case explicitly tested
- [ ] `docs/STRATEGY_FORMAT.md` exists and is verified against the validator
- [ ] `sync_strategies` removed; app-authored strategies survive an engine run
- [ ] Full offline test suite green
